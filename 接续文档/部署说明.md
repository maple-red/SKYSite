## 1. 把代码传到服务器（打包上传）

别直接拖整个文件夹（node_modules 几百 MB 传半天），**本地打成一个小包再传**。

### 1.1 本地打包（Git Bash 里执行）

```bash
cd /d/MyWebsite
tar -czf skyl1n-test1.0.2.tar.gz \
  --exclude='./frontend/node_modules' \
  --exclude='./frontend/dist' \
  --exclude='./backend/target' \
  --exclude='./backend/data' \
  --exclude='./.git' \
  --exclude='./.idea' \
  --exclude='./.claude' \
  --exclude='./开发日志' \
  --exclude='./.playwright-mcp' \
  --exclude='./skyl1n*.tar.gz' \
  .
```

生成一个 **1~2MB** 的 `skyl1n-test1.0.2.tar.gz`（只含源码和部署文件，**换版本号 +1 再打**）。

### 1.2 WinSCP 只传这一个包

把 `skyl1n-test1.0.2.tar.gz` 传到服务器，比如 `/root/` 下。

### 1.3 服务器上解压

```bash
mkdir -p /opt/skyl1n && cd /opt/skyl1n && tar -xzf /root/skyl1n-test1.0.2.tar.gz
ls /opt/skyl1n   # 确认看到 backend/ frontend/ docker-compose.yml .env
rm /root/skyl1n-test1.0.2.tar.gz   # 解压完压缩包就没用了，删掉
```

> 记得 `docker-compose.yml` 必须解压在 `/opt/skyl1n/` 最外层。

## 2. 配 Docker 镜像加速（国内服务器必做，否则拉镜像卡死）

1. 去你的云厂商控制台找"容器镜像服务 → 镜像加速器"，复制专属地址（形如 `https://xxx.mirror.aliyuncs.com`）
2. 服务器上执行：
   ```bash
   sudo mkdir -p /etc/docker
   sudo tee /etc/docker/daemon.json <<'EOF'
   { "registry-mirrors": ["https://xxx.mirror.aliyuncs.com"] }
   EOF
   sudo systemctl restart docker
   ```

## 3. 启动

```bash
cd /opt/skyl1n
docker compose up -d --build
```

第一次会拉镜像 + 构建前后端，国内服务器约 3~10 分钟，看进度：
**之后更新重建**：镜像和依赖都缓存了，通常几十秒到几分钟，详见 6.1。

```bash
docker compose ps          # 三个容器都应为 Up
docker compose logs -f backend   # 等 Spring Boot 启动完成
```

## 4. 验证

```bash
curl http://localhost               # 返回 HTML 页面
curl http://localhost/api/stats     # 返回 {"totalVisitors":...}
```

浏览器访问 `http://你的服务器IP`。

### 4.1 HTTPS 跳转说明（自签证书方案，旧）

> 早期方案：项目内置自签证书，访问 `https://IP` 会 301 跳回 `http://`。
> 现已升级为**正式证书**（见 4.2），此节仅留作历史参考。

- 自签证书浏览器不信任，第一次访问弹"连接不是私人连接"警告
- 无论哪种方案，云控制台安全组都要放行 443

### 4.2 SSL/HTTPS 正式证书配置（当前方案）

> 域名 `linyou.cloud`（含 `www.linyou.cloud`），Docker Compose + nginx 正式 SSL 证书。
> 证书文件在 `frontend/certs/`（`cert.pem` 证书链 + `key.pem` 私钥）。

**部署前必须配置：**

1. **DNS 域名解析**（云厂商 DNS 控制台），`@` 和 `www` 都配 A 记录指向服务器 IP：
   ```
   @（linyou.cloud）  A  服务器IP
   www              A  服务器IP
   ```
   只配一个，另一个打不开。

2. **云控制台安全组/防火墙**放行入方向：TCP 80 / 443 / 22。

3. **确认证书覆盖 www**：
   ```bash
   openssl x509 -in cert.pem -noout -text | grep -A1 "Subject Alternative Name"
   ```
   - 含 `DNS:linyou.cloud, DNS:www.linyou.cloud` → 裸域名和 www 都正常
   - 只有裸域名 → `https://www.linyou.cloud` 会证书警告，用裸域名即可

**nginx 配置要点**：80 → 301 跳 https；443 用正式证书主服务；`server_name linyou.cloud www.linyou.cloud`；frontend 容器挂载 `./frontend/certs:/etc/nginx/ssl:ro`。

**访问**：`https://linyou.cloud`（正式证书，浏览器显示锁图标）；`http://linyou.cloud` 备案未通过时被拦「未备案」。

## 5. 常见问题

| 症状 | 原因 | 解决 |
|---|---|---|
| 8088 一直重启 | MySQL 还没就绪 | 正常现象，等 MySQL 起来后会自动连上 |
| 80 端口起不来 | 被别的程序占了（宝塔/nginx） | `sudo ss -tlnp \| grep :80` 查看，停掉占用的 |
| 外网打不开 | 防火墙/安全组没放行 | 云控制台安全组 + `sudo ufw allow 80` 放行 80 端口 |
| 构建卡在 npm | 服务器访问不了 npmjs | 已内置 npmmirror 源，还卡就检查外网 |
| 构建卡在 apk/openssl | 国内访问 alpine 源慢 | Ctrl+C 重跑一次构建，一般能过 |
| https 打不开 | 安全组没放行 443 | 云控制台放行 TCP 443 端口 |
| FORWARD 策略是 DROP，怕防火墙坏了 | Docker 默认行为，不是坏了 | 不用管，Docker 的 DOCKER 链已显式放行 80/443 |
| 访客数字不涨 | 唯一访客设计，同浏览器只算一次 | 换浏览器/无痕/手机才会 +1，正常现象 |

## 6. 日常运维

```bash
docker compose ps              # 看状态
docker compose logs -f backend # 看后端日志
docker compose restart backend # 重启后端
docker compose down            # 停（数据还在卷里）
```

### 6.1 更新部署（重传重构建）

改完代码要更新线上时：

1. 本地重新执行 1.1 打包 → 得到新的 `skyl1n.tar.gz`
2. WinSCP 传到服务器，**直接解压覆盖**（不需要先删旧文件夹）：
   ```bash
   cd /opt/skyl1n && tar -xzf /root/skyl1n-test1.0.2.tar.gz
   docker compose up -d --build
   ```
3. **重建很快**：基础镜像、npm 依赖、没改的后端都命中 Docker 缓存，只有改动的部分重新构建（前端约十几秒）
4. **数据自动保留**：`mysql-data` 卷不会被清；`up -d` 只重建有变动的容器，后端和 MySQL 通常不动

> 注意：如果服务器上的 `.env` 改过密码：解压会用 tar 里的覆盖回默认值，导致 MySQL 密码对不上 → 改过的先备份 `.env`，解压后改回来

## 7. 改数据库密码

只改服务器上 `.env` 里的 `MYSQL_ROOT_PASSWORD`，然后：
```bash
docker compose down && docker compose up -d --build
```
> 注意：只改密码要清掉旧数据卷才会生效：`docker volume rm skyl1n_mysql-data`（**会清空数据**，谨慎）

## 8. 防火墙（入站规则，可选但推荐）

只放行 SSH(22) 和网站端口，其余入站全拒绝：

```bash
# ① 本机回环放行
sudo iptables -A INPUT -i lo -j ACCEPT
# ② 已建立的连接放行（否则 SSH/网页响应会被拦断）
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
# ③ 放行 22、80、443
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
# ④ 其余全部拒绝（顺序别乱，③ 必须在 ④ 前）
sudo iptables -A INPUT -j DROP

# 保存（否则重启丢失）
sudo apt install -y iptables-persistent
sudo netfilter-persistent save
```

> 注意：SSH 若不在 22 端口，改 ③ 里的端口，否则会把自己锁门外。
> 注意：这套规则管的是**宿主机自己监听的端口**；Docker 容器的 80/443 走 FORWARD 链（Docker 自己管理，FORWARD 策略 DROP 是正常现象，见第 5 节），不受影响。
> 云控制台安全组也要放行 80/443/22——那是另一套独立规则，两套都要放行才通。
